# Mochi 3.0 → v5: what moved, and what is safe to delete

> Audited 2026-08-04 against `archive/mochi-3.0/` at 304 tracked files.
> Written to answer one question: **can the 3.0 tree be deleted without
> losing anything?** Answer: yes, with two named exceptions below.

---

## Tools and windows

3.0 shipped 13 GUI entry points. Every one has a live equivalent.

| Mochi 3.0 | v5 | Notes |
|---|---|---|
| `tools/sprite_editor_gui.py` (606) | [interfaces/sprite_editor.py](../../interfaces/sprite_editor.py) | Characters → Sprite Editor. Same `.mscript` grammar, round-tripped in tests. |
| `tools/mscript_editor_gui.py` (253) | [interfaces/mscript_editor.py](../../interfaces/mscript_editor.py) | Its own tab. `[Resources]` add/edit/remove came across. |
| `tools/mochi_studio.py` → `BitmapEditorWidget` | [interfaces/bitmap_editor.py](../../interfaces/bitmap_editor.py) | Characters → Bitmap Editor. MSB-first row padding preserved. |
| `tools/mochi_studio.py` → `MscriptTextEditor`, `ResourceEditorDialog` | `interfaces/mscript_editor.py` | Editor pane + Resources pane. |
| `tools/mochi_studio.py` → `SpriteEditorWidget` | `interfaces/sprite_editor.py` | |
| `gui/mochi_gui.py` (619) | [player.py](../../interfaces/player.py) + [runtime.py](../../interfaces/runtime.py) + [modules.py](../../interfaces/modules.py) | Control panel split three ways: playback, raw display command, node/slot status. |
| `gui/mochi_vdisplay.py` | [interfaces/virtual_display.py](../../interfaces/virtual_display.py) | Windows tab. |
| `gui/mochi_vdisplay_player{,_qt}.py` | [interfaces/popup_player.py](../../interfaces/popup_player.py) | Skins and settings contract covered by tests. |
| `gui/mochi_perf.py` | [interfaces/performance.py](../../interfaces/performance.py) | Windows tab. |
| `gui/llm_chat_gui.py` | [interfaces/chat.py](../../interfaces/chat.py) | Layout only — see the gap below. |

The 3.0 editors were standalone scripts you pointed at a file. v5 keeps that:
the Characters tab has an **Editor** picker so the sprite and bitmap editors
open regardless of which pack is loaded, and the bitmap editor has its own
**Open…**. Without those two the ports were reachable only when the selected
character happened to match, which is not the same tool.

## Engine, transport, content

| 3.0 | v5 |
|---|---|
| `plugins/animation_node/` (24 files) | the `jaeger-animation` module, bound to the `animation` slot |
| `core/` (8 files — broker, node base, ZMQ, topics) | the `jaeger-os` framework |
| `assets/` (242 files) | `assets/` and the pack that uses them under `characters/` |
| `config.yaml`, `run.sh`, `main.py` | `jaeger.toml` + `main.py` |
| `docs/messaging.md` | `dev/docs/v4-era/messaging.md` (same doc, paths updated) |

**Assets: 242 of 242 accounted for.** 201 kept their path under `assets/`;
39 moved into the character pack that owns them (`patric_emotes.bmp` →
`characters/Patric/assets/`, the video splits → `characters/mochi/assets/`,
the bitmap faces → `characters/bitmap man/assets/source/`). The last 2 were
loose reference images and are now copied to `assets/png/`.

All 26 procedural scenes are in `assets/math/`:

```bash
python3 main.py --asset assets/math/wave_scene.py
```

## Not migrated, on purpose

- **`tools/monitor_cli.py`, `gui/control_cli.py`.** Both open ZMQ sockets
  (`tcp://127.0.0.1:5560`, `:5556`) that v5 does not bind — the bus is
  in-process. There is no port, only a rewrite against the JaegerOS control
  plane, and nothing needs it today. `main.py --nodes` answers the inventory
  half from live discovery.
- **`tools/bitmap_editor_gui.py`.** Despite the name it is a *frame-sequence
  player* (Load Frame(s), FPS, Play/Pause), not a pixel editor. The media
  player and popup player cover playback; the editing half came from Studio.
- **`tools/test_smoke.py`.** Validated 3.0's `config.yaml` broker/monitor
  addresses and plugin entries. Nothing it checked still exists; `dev/tests/`
  and `main.py --nodes` replace it.
- **`tools/mochi_studio.py` → `AssetPreviewer`.** The 128px thumbnail cache
  for the file browser. No v5 surface has a thumbnail browser to put it in.

## ~~The one real gap~~ — closed 2026-08-05

**`plugins/llm_node/` (4 files) now has a v5 home.** JaegerAgent fills the
`mind` slot; `modules/jaeger_agent.py` is the integration and `interfaces/chat.py`
is the tab. None of 3.0's code was lifted — it was a ZMQ node against 3.0's
`core/` — but the shape survived, one layer up:

| `llm_node/config.yaml` | v5 `[config.mind]` |
|---|---|
| `model: gemma3:12b` | `provider = "llama_cpp"` + a discovered `.gguf` |
| `ollama_host` | `base_url`, only when `provider` is served |
| `system_prompt` | `system_prompt` |
| `subscribe: stt.text` → `publish: llm.reply` | `/act/chat` → `/sense/chat` |

`ollama_client.py` (87 lines of `/api/chat` POST) has no successor and needs
none: the module owns the provider client, and Ollama is now three config
keys rather than a file.

The one thing 3.0 had that v5 does not is the STT → mind wiring — 3.0's node
subscribed to `stt.text` directly, so speaking to it worked. In v5 the Chat
tab echoes `/act/chat` rather than only what it sent, so routing transcripts
there is a subscription, not a redesign. Nobody has done it yet.

## Verification

```bash
python3 -m pytest dev/tests -q
```

`test_window_gallery_only_offers_archives_that_are_still_on_disk` is the one
that matters for the deletion: the Windows tab lists only archives present on
disk, so removing `archive/mochi-3.0/` drops its ten rows instead of leaving
buttons that cannot start anything.
